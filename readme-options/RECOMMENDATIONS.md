# Profile README recommendations

Recommended starting point: README-systems-brief.md.

- Put your role, strongest competencies, contact links, and impact in the first screen.
- Use one branded SVG banner instead of stacking pipeline, Mermaid, and activity visuals before the work.
- Link directly to RDKit discussions and personal repositories. Distinguish proposals from shipped changes; these alternatives intentionally do not assert merge status.
- Keep scientific computing prominent as a differentiator alongside developer infrastructure and C++ performance.
- Separate core experience from exploratory interests such as Go backends.
- Remove the placeholder OSS pulse until the generator is scheduled and producing current data. GitHub already shows activity below the README.
- Replace internal commentary about “signals” and generic cleanup with the engineering problem and your work.
- Keep all material facts as readable Markdown, not only text inside images.

Metrics are retained from your website and earlier portfolio work. Add project-specific scope, measurement conditions, and ownership when you can disclose them. Public RDKit issue links are references, not independently verified merge-status claims.

These previews approximate GitHub Markdown styling. They do not depend on scripts or custom CSS inside the README; the selector and theme toggle exist only in the local comparison page.

To adopt a variant, copy its Markdown to the repository root README.md and its matching SVG from assets/ into the repository root assets/. Keep the existing README until a direction is selected.
